# 릴리스 만드는 법

깃허브 **Releases** 는 "이 시점의 파일 묶음 + 설명" 을 고정 주소로 걸어 두는 곳입니다.
저장소에 파일을 올리는 것과 별개입니다 — 파일은 먼저 올려 두시고, 그다음에 릴리스를 겁니다.

이 폴더에 저장소별 본문 세 개가 있습니다. **그대로 복사해 붙여넣으면 됩니다.**

---

## 공통 절차

1. 저장소 → 오른쪽 **Releases** → **Draft a new release**
2. **Choose a tag** → 아래 표의 태그를 입력하고 **Create new tag on publish** 클릭
3. **Release title** 에 제목 입력
4. 본문(Describe this release)에 해당 `.md` 파일 내용을 붙여넣기
   *(맨 위 `<!-- ... -->` 주석 줄은 지우셔도 되고 두셔도 됩니다 — 화면에는 안 보입니다)*
5. **Attach binaries** 에 첨부 파일을 끌어다 놓기
6. **Publish release**

## 순서 추천

**1) `ss2-sp-runner` 먼저.**
Pages 라서 파일을 올리는 즉시 눈으로 확인됩니다. 실행이 되는 걸 보고 릴리스를 거세요.

**2) `ss2-sp-core`.**
`cores/` 폴더의 세 파일을 그대로 첨부하면 됩니다. 저장소에도 있고 릴리스에도 붙는 게 맞습니다 —
저장소 것은 소스와 같이 보는 용도, 릴리스 것은 사람들이 받아 가는 용도입니다.

**3) `emu-ex-plus-alpha` 마지막.**
파일을 먼저 올리고 → **Actions → build → Run workflow** → 빌드가 끝나면 APK 가 나옵니다.
그 APK 를 첨부해서 릴리스 본문을 갈아 끼우세요.
직링크(`.../releases/download/Pre-release/NgpEmu.apk`)를 살리려면
`buildyml_edit.md` 의 두 줄 수정을 먼저 하셔야 합니다.

## 알아 두면 좋은 것

- **태그는 나중에 못 바꿉니다.** 지우고 다시 만들 수는 있지만 링크가 끊깁니다.
  `v0.7` 처럼 짧게 맞춰 두면 나중에 정렬이 깔끔합니다
- **첨부 파일 이름은 영문으로.** 한글 이름은 브라우저나 압축 도구에 따라 깨집니다
- **본문은 나중에 고쳐도 됩니다.** Edit release 로 언제든 바꿀 수 있습니다
- 릴리스를 걸면 저장소를 지켜보는 사람에게 알림이 갑니다. 여러 번 고칠 거면
  **Set as a pre-release** 로 걸어 두었다가 나중에 정식으로 올리는 방법도 있습니다
- **롬은 어디에도 첨부하지 마세요.** 저장소·릴리스·Pages 전부입니다
