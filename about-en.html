Why

Specials don't come out. But the worse failure is the other one: you input it correctly and a different move fires.

I disassembled the ROM. The command matcher (0x202E8B) walks the input ring backwards and skips samples that don't match — it wants a subsequence, not a contiguous run. Leftovers from your previous input let a short command satisfy itself first and eat the longer one.

The fix turned out to be one byte. Writing 1 to 0x1DCD runs the game's own ring-reset routine — an existing code path, zero extra frames.

You never think about facing

The facing flag is read from RAM (0x0E54) and the command is mirrored for you. Same button on either side. That's why there is no flip switch.

Not a cheat
  • creates no moves that don't exist
  • modifies no game data
  • hitstop still blocks it
  • air-state gating still applies
  • a whiffed throw still whiffs

All it does is supply inputs.

Side finding

The browser build stuttered while a finger was on the screen. It wasn't my code. EmulatorJS hands emscripten a canvas with alpha:true, so the compositor blends it against the page on every composite, starving the emulator loop exactly when the compositor is already busy.
